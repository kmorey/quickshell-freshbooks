# Establish FreshBooks timer semantics

## Question

What authoritative FreshBooks API behavior and constraints govern running and paused timers, duration corrections, timer-to-entry logging, switching projects, remote changes, billability inheritance, entry editing/deletion, local date boundaries, and timers crossing midnight?

## Blocked by

- None

## Resolution

[FreshBooks timer semantics](../../docs/research/freshbooks-timer-semantics.md) establishes the documented Time Entry/timer state model, safe log-then-start switching boundary, remote-refresh mechanisms, billability and local-date rules, and the API gaps that require live-account characterization. In particular, pause/resume, correction of a still-running duration, concurrency guarantees, and midnight-crossing behavior are not specified by FreshBooks' public contract and must not be implemented from guessed payloads. Research was written directly to the shared tree because branch capture was unavailable in this non-Git folder.

# Chart the FreshBooks time-tracking plugin

## Destination

An implementation-ready product and technical specification for a reusable, single-user-first Omarchy 4 Quickshell plugin that manages FreshBooks time through `freshbooks-cli`, including timer/project switching, entry editing, and calendar review.

## Notes

- Domain: FreshBooks time tracking presented as a native-feeling Omarchy 4 Quickshell experience.
- Every session should consult the `domain-modeling` skill and [the project glossary](../../CONTEXT.md); ticket-specific skills are named by each ticket label.
- `freshbooks-cli` is the exclusive integration boundary and may be extended in its own repository as necessary.
- FreshBooks is authoritative; local state is limited to preferences, cache, and recoverable drafts.
- The plugin presents one Active Timer even though FreshBooks can contain multiple unlogged timers. A Timer Switch must log the selected timer before starting another project, and failure must preserve it.
- The compact UI has timer/editor and Projects tabs; calendar/history is an expanded view.
- Reporting follows FreshBooks-local dates and Sunday–Saturday weeks. Initial totals ignore billability because Time Entries inherit it from their project.
- Successful operations are quiet; failures remain visible and actionable. Full keyboard operation is required.
- Research findings are written directly into this folder because no Git repository exists yet; throwaway research branches are therefore unavailable.

## Decisions so far

- [Establish FreshBooks timer semantics](WF-002.md): Timers are unlogged Time Entries, log-then-start is the safe switch boundary, and undocumented mutations require controlled live-account characterization.
- [Audit freshbooks-cli's time-tracking surface](WF-003.md): The CLI-only approach is viable, with explicit additions needed for stable schemas, timer mutations, safe switching, conflict detection, and bounded process behavior.
- [Map Omarchy 4's Quickshell extension seams](WF-004.md): Use a root-manifest service plus bar-widget plugin, with singleton CLI/state ownership and a clock-shaped keyboard popup expanding to calendar/history.

## Not yet specified

- Visual composition, focus behavior, loading/empty/error states, and accessibility details beyond the agreed two-tab and expanded-calendar shape.
- Local cache format, draft recovery, migration policy, and refresh scheduling after synchronization behavior is decided.
- Repository/package structure, automated and manual test strategy, acceptance scenarios, implementation milestones, and release/distribution workflow after the major interfaces settle.

## Out of scope

- Invoicing, expenses, general reporting/export, multi-account switching, manual billability controls, and non-FreshBooks backends.
- Implementing the plugin or CLI changes during this planning map unless the map's Notes are explicitly amended to include execution.

# Characterize undocumented timer mutations in a live account

## Question

Using a controlled FreshBooks project and authenticated development CLI, what observable request, response, and cross-client behavior occurs for pause, resume, correcting a running duration, multiple simultaneous unlogged timers, stale writes, logging failures, remote edits, and crossing local midnight?

## Blocked by

- None

## Progress

[FreshBooks live timer characterization](../../docs/research/live-timer-characterization.md) records the sanitized, cleaned-up observations for timer segmentation, pause/resume state, Duration Correction, consolidation/rounding on log, stale writes, and public Time Entry endpoint limitations. The web UI's two-request timer start shape is now captured: a blank unlogged Time Entry POST with `timer: {}` creates the timer identity, then a PUT assigns the selected project, service, identity, and note. The remaining blocker is capturing and validating the non-secret request shapes for pause and resume.
